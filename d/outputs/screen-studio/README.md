# Screen Studio

SI 프로젝트 초반, 기획자가 요구사항을 등록하고 샘플 UI·버전별 메모·화면설계서를 관리하는 실행 가능한 웹 애플리케이션 소스입니다.

## 실행

Node.js 24 이상을 설치한 환경에서 이 폴더를 열고 실행합니다.

```powershell
npm install
npm test
npm start
```

브라우저에서 http://127.0.0.1:4317 에 접속합니다. 첫 화면의 **샘플 프로젝트로 둘러보기**로 고객 관리 예제를 생성할 수 있습니다. 별도 프런트엔드 빌드가 필요 없습니다.

## 사용 흐름

1. 프로젝트명과 업무 전체 설명을 등록합니다.
2. 요구사항 정의 탭에서 직접 입력하거나 엑셀 양식을 다운로드해 작성 후 업로드합니다. 업로드는 초안을 대체하며 저장 버튼으로 확정합니다.
3. 새 버전 UI 생성에서 생성 방식과 변경 내용을 입력합니다. 요구사항 저장 후 화면 스냅샷을 생성합니다.
4. 화면 목록에서 조회·등록·상세 샘플을 확인하고, 화면 전체 또는 필드별 메모를 작성합니다.
5. 화면설계서 PPT 다운로드로 선택한 버전의 전체 화면과 가정·메모를 내보냅니다. HTML 다운로드는 개발자가 API를 연결할 수 있는 독립적인 화면 껍데기를 제공합니다.
6. 버전 이력에서 과거 UI를 확인하거나 과거 요구사항을 현재 초안으로 복사합니다. 생성된 버전의 요구사항/UI는 변경하지 않습니다. 메모는 해당 버전에 별도로 누적됩니다.

## 엑셀 양식

`.xlsx`, 최대 2MB, 최대 100개 화면. 시트명은 `요구사항`, 헤더 순서는 `화면 ID / 화면명 / 업무 설명 / 메뉴 경로 / 화면 유형 / 필드`입니다. 처음 네 항목이 필수입니다. 화면 ID는 영문·숫자·밑줄·하이픈 40자 이내이며 프로젝트 안에서 유일해야 합니다. 유형은 자동/조회/등록/상세, 필드는 쉼표로 구분해 최대 12개입니다. 수식은 허용하지 않습니다. 오류가 있으면 전체 업로드를 거절해 부분 저장을 방지합니다.

## AI 설정

`.env.example`을 `.env`로 복사한 뒤 `OPENAI_API_KEY`, 사용 가능한 `OPENAI_MODEL`을 설정하고 서버를 재시작합니다. 키는 서버에만 저장합니다. AI 모드에서 프로젝트 설명과 요구사항을 OpenAI Responses API로 전송하고, JSON 결과를 검증한 뒤 서버의 안전한 화면 템플릿으로 렌더링합니다. 모델이 반환한 HTML이나 코드를 실행하지 않습니다. API 실패 시 샘플 모드로 자동 전환하지 않고 오류를 표시합니다. 공식 API: https://developers.openai.com/api/reference/resources/responses/methods/create

키가 없으면 **규칙 기반 샘플 모드**를 사용할 수 있습니다. 고객·주문·인사 등의 업무 키워드로 기본 필드를 제안하는 방식으로, AI 추론과 구분해 화면과 문서에 표시합니다.

## 구성과 저장

- `server.mjs`: HTTP API, SQLite 저장, 엑셀 처리, AI 요청, PPT/HTML 출력
- `domain.mjs`: 요구사항/AI 출력 검증, 샘플 생성, HTML 렌더러
- `public/`: 한국어 반응형 프런트엔드
- `test/`: 필수값, AI 출력, 생성 및 HTML 이스케이프 검증
- `data/studio.sqlite`: 실제 프로젝트 저장소. 백업 시 서버를 종료한 뒤 data 폴더 전체를 보관하세요.

초안은 revision을 검사해 다른 창의 수정 내용을 덮어쓰지 않습니다. 생성 중 초안이 바뀌면 버전 생성을 거절합니다. 프로젝트별 동시 생성을 막고 버전 번호에는 DB 유일성 제약을 적용합니다.

## PPT 고정 양식

16:9 표지 → 화면별 설명 및 UI 요소 표 → 화면별 설계 가정과 검토 메모 순서입니다. 화면은 동일한 화면 스키마에서 PPT 기본 표/텍스트 객체로 재구성합니다. 브라우저의 픽셀 단위 스크린샷과 동일한 레이아웃은 아니며, 표와 텍스트를 PowerPoint에서 수정할 수 있습니다. 메모는 3개씩 추가 슬라이드로 분할합니다.

## 운영 범위

현재 버전은 로컬 단일 서버 검토용 MVP입니다. 로그인, 사용자별 프로젝트 권한, 회사 SSO, 배포 설정은 포함하지 않습니다. 기본적으로 127.0.0.1에서만 접속합니다. 사내 공동 운영 전 인증/권한, HTTPS, 백업 정책, AI 전송 데이터 정책과 업로드 자원 제한을 배포 환경에 맞게 추가해야 합니다. 샘플 화면의 버튼은 안내 메시지만 표시하고 업무 처리/API 호출을 하지 않습니다.

## 검증 상태

2026-09-14 Windows / Node.js 24.18.0에서 의존성 설치 및 테스트 6개 통과를 확인했습니다. 기본 PowerShell의 프로세스 시작 오류는 cmd.exe 실행으로 해결했습니다. 프로젝트의 `.npmrc`는 npm 캐시를 프로젝트 내부에 두어 사용자 전역 캐시의 쓰기 권한 문제를 피합니다.

실제 HTTP 서버를 사용하는 통합 테스트로 엑셀 양식 다운로드·업로드·필수값 오류 거절, 초안 저장 충돌 방지, UI 생성, 메모 저장, HTML/PPT 생성, PPT 내부 슬라이드/메모 존재, 새 버전 생성 후 이전 버전 보존을 확인했습니다. 브라우저에서 샘플 프로젝트 생성·화면 표시·메모 저장도 확인했습니다. 이메일이 날짜로 표시되던 샘플 데이터 오류를 수정하고 회귀 테스트를 추가했습니다.

실제 AI 호출은 API 키/모델이 없어 검증하지 않았습니다. PPT는 파일 생성과 내부 문서 구조/내용을 검사했으며 PowerPoint에서 시각 검증하지 않았습니다.

의존성 점검에서 uuid를 11.1.1로 고정해 관련 경고를 해소했습니다. `pptxgenjs → image-size`의 이미지 파서 취약점으로 npm audit 경고 2개(high)는 남아 있습니다. 확인 시점 최신 image-size 2.0.2에도 수정 버전이 없으며, 이 프로그램의 PPT 출력은 이미지 입력을 사용하지 않습니다. 이미지 삽입 기능을 추가하기 전 해당 의존성을 재점검해야 합니다.
